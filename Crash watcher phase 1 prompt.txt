2. Strategy Rules

The strategy is called:

YELLOW HUNTER

Crash multipliers have three categories:

- RED: multiplier below 2.00
- GREEN: multiplier from 2.00 to 9.99
- YELLOW: multiplier equal to or above 10.00

The strategy must operate using confirmed round results.

STATE 1 — WAITING_FOR_YELLOW

Initially, the strategy is inactive.

Wait until a confirmed yellow result (10.00 or higher) arrives.

This yellow result is the trigger.

IMPORTANT:
The trigger round itself is NOT a bet.

After receiving the trigger:

- Activate a new cycle.
- Set attempt number to 0.
- Set remaining attempts to 10.
- Transition to ACTIVE_CYCLE.

STATE 2 — ACTIVE_CYCLE

The strategy tracks the NEXT 10 completed rounds.

Each subsequent completed round represents exactly one simulated bet.

The bet:

- Always targets YELLOW.
- Always uses the same fixed amount.
- Does not increase after losses.
- Does not use Martingale.
- Does not use progressive staking.

For each completed round:

IF multiplier >= 10.00:

- Register a simulated WIN.
- Mark the current cycle as WON.
- Immediately terminate the cycle.
- Reset attempt number to 0.
- Reset remaining attempts.
- Return to WAITING_FOR_YELLOW.
- Do not reuse this winning yellow as a new trigger.

IF multiplier < 10.00:

- Register a simulated LOSS.
- Increase attempt number by one.
- Decrease remaining attempts by one.

IF attempt number reaches 10 without a yellow result:

- Mark the cycle as EXPIRED.
- Stop registering bets.
- Reset the strategy state.
- Return to WAITING_FOR_YELLOW.

A win on ANY attempt from 1 to 10 must immediately terminate the cycle.

5. Strategy Engine API

Design a simple public interface.

Example:

engine = StrategyEngine(
config=StrategyConfig(
fixed_bet_amount=10,
max_attempts=10,
yellow_threshold=10.0
)
)

result = engine.process_round(
round_id="round_001",
multiplier=12.45
)

The engine should return a structured result describing:

- Round ID
- Multiplier
- Multiplier category
- Previous strategy state
- Current strategy state
- Whether a cycle was triggered
- Whether a simulated bet was registered
- Bet amount
- Attempt number
- Remaining attempts
- Bet outcome: WON, LOST, or NONE
- Cycle outcome: ACTIVE, WON, EXPIRED, or NONE
- Event timestamp

Use structured Python objects, not unstructured dictionaries where avoidable.

6. Duplicate Protection

The same round must NEVER be processed twice.

Implement round ID validation.

If an already-processed round ID is submitted again:

- Do not change the strategy state.
- Do not register another simulated bet.
- Return a clear duplicate-event result.

Round IDs must be unique.
